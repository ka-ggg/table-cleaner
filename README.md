# 表格清洗小工具

**当前版本：v2.4.0（自动化测试总数见下方「确认你在跑哪个版本」；v2.3.0 的 306 项全部保留）**

帮小商家和办公人员快速清理 CSV / XLSX：检查空值、重复行和可疑格式，按需删行、改列、算新列，
一次处理多张工作表或多个文件，导出干净文件。中文界面，按手机屏幕适配；
没有登录、数据库、支付和外部接口。v2.3.0 起还可以脱离网页，用命令行（预览版）或
Python 公共 API 调用同一套清洗逻辑。
（手机浏览器里的**人工**验收本轮未完成，原因见「真机验收清单」最后一节，不当作已通过项。）

> 公共 API 清单见 [`API.md`](API.md)；benchmark 首版基线见 [`benchmarks/BASELINE.md`](benchmarks/BASELINE.md)。
> 命令行是**预览版**，参数兼容承诺自 v3.0 起算。

## v2.0.1 的改动（行为基线：只修 bug，不加功能）

这一版来自一次从零开始的商业化交付审查（见 `AUDIT_REPORT.md` / `BUGS_AND_FIXES.md`）。
修的都是**会让用户拿到错数据或让页面不可用**的问题，行为口径变化如下：

- **长编号不再被「转数字」改值**：超过 15 位有效数字的订单号/身份证号/条码，
  在「转数字」和 XLSX「尝试转数字」模式下**保持文本**（旧版会被截成 9223372036854775807
  或丢掉尾数，而且没有任何提示）。`00123 → 123` 这类预期效果不变。
- **计算列不再卡死页面**：`9**9**9`、`10**100000000` 这类指数爆炸会在求值前被拦住并给中文提示；
  页面上不再出现「点了没反应、手机滚烫」的情况。
- **计算列不再静默回绕**：整数溢出（如 `4000000000*4000000000`）改成按 Excel 一样的双精度浮点算，
  结果溢出时留空并提示，不再出现「负数/怪数」。
- **日期列混时区不再整页崩**：同一列既有 `+08:00` 又有不带时区的日期时，整列保留原文并提示，
  不再整页变成 `ValueError: Mixed timezones detected…` 的英文堆栈。
- **模板「列顺序」不再失效**：引用了改名后/计算出来的列名时不再被当成「不存在的列」丢掉。
- **数据区合并单元格会提示**：合并区域只有左上角有值，勾「删除空值行」前会提醒，
  避免把合并区域里的行当空行删掉。
- **`round()` 不再能卡住页面**：`round(1, -10000000)` 会去算 10 的 1000 万次方（实测 18 秒），
  现在保留位数限制在 ±30 内，超出立刻中文提示。
- **整列都是长整数的编号也守住精度**：第一轮修复在「纯 18 位整数列」上会失效
  （pandas 给出精确的 int64，守卫按 int64 比对就放行了），导出的 XLSX 里两个不同身份证号
  会并成同一个值。现在守卫以 float64（Excel 真正存数字的精度）为准，已补回归测试。
- **`-3%` 这类负百分比不再被当成公式**：原来导出会变成 `'-3%`，工具自身往返一次就改了值。
- **XLSX 里以文本保存的编号原样保留**：`00123` 不会再被 pandas 推断成 `123`；
  数字/日期列仍按正常类型读（不是整张表变字符串）。
- **测试在干净环境也能跑**：4 项 XLSX 测试对 XML 序列化格式过严，
  在没有 lxml 的干净 venv 里会失败（也就是 CI 会红），已改成两种写法都认。
- 文档同步：重复列名的实际命名（`金额.1`）、百分比/货币格式不保留、长编号在 XLSX 里的精度限制等，
  都写进了「已知限制」和 `FAQ.md`。

## v2.0.0 的功能改动（上一版）

### 1. 功能边界（最高优先级）

- **一次处理多张工作表**：第 7 步「批量处理」，勾选同一工作簿里的多张表，各自清洗后
  打成一个 ZIP（每张表一个 CSV/XLSX 文件），不再需要一张张手动切换、下载。
- **批量上传多个文件**：同一个地方可以一次选多个 CSV/XLSX，按文件分别清洗后一起打包。
  单项失败（坏文件、超限表）只记录原因，不影响其他项；页面表格逐项列出「来源 / 清洗前 /
  清洗后 / 结果」。
- **清洗规则模板（JSON）**：把当前这套规则（表头行、全行去重、按列去重、删空值行、
  列重命名、删列、列顺序、类型转换、计算列）存成一个 JSON 文件下载；下次上传同类表格，
  上传模板即可一键还原。模板只存在浏览器会话里 + 可下载的 JSON，不依赖服务器/数据库，
  不含任何数据。
- **指定表头行**：可选「表头在第几行」（默认第 1 行），报表上面有标题行的文件不用先手工处理。
  **合并单元格造成的空表头**会自动命名成「列3」这类名字（否则下拉框里选不到这一列），
  改名可以在第 4 步做。
- **进阶列操作（全部可选、默认关闭）**：
  - 列重命名（界面里按「旧列名=新列名」逐行填写）；
  - 简单类型转换（文本 → 数字 / 日期，**失败保留原文并提示**是哪个格子）；
  - 删列、把指定列排到最前面；
  - 简单计算列（如 `总额=单价*数量`），用白名单表达式求值，**不执行任意代码**。

### 2. 性能与规模

- **可配置硬超时**：默认 60 秒，左侧「高级设置」或环境变量可调，0 = 不限。
  超时给中文提示（告诉用户拆文件 / 调大秒数），本次不生成下载，内存随会话结束释放。
- **超过 10 万行默认分块清洗 + 进度条**：按 5 万行一块处理「删空值行」，块之间更新进度、
  检查超时；手机端不会看起来像卡死。去重仍是一次精确比较（跨块去重需要留全部键，
  反而更占内存），所以分块不改变结果——测试里逐项比对过「分块 = 整表」。
- **所有 `MAX_*` 集中到 `cleaning/limits.py`**，支持环境变量覆盖（见「资源限制」），
  界面侧边栏还能按会话临时覆盖上传大小和行数上限（不改全局，不影响别人的会话）。
- **公网部署建议**（反向代理超时 + 容器内存上限）写进本文「部署」一节的
  「公网部署前必须设的两个数」。

### 3. 导出与兼容性

- **CSV 公式注入防护改成三种模式**（第 6 步单选）：
  1. 加英文单引号 `'`（默认，兼容性最好）；
  2. 前缀零宽空格 `U+200B`（单元格里看不见，但搜索/文本比较会受影响）；
  3. 关闭防护（完全按原样导出）。
- **XLSX 编号类字段两种处理**（第 6 步单选）：
  - 「强制文本」（默认）：`00123` 保持 `00123`，不会被 Excel 吃掉前导零；
  - 「尝试转数字」：`00123 → 123`、`1,000 → 1000`，`A002` 这种转不了的**保留文本**。
- **导出文件名自动带原文件名和时间戳**：`清洗后_订单_20240501-123005.csv`，
  连续导出不会互相覆盖；批量 ZIP 里同名条目自动加 ` (2)`。
- XLSX 的 `=` 开头的文字仍强制按文本写入（防止打开时被当公式执行）。

### 4. 代码结构与可维护性

- **`cleaning.py`（744 行）拆成 `cleaning/` 包**，职责清晰、每块都能单独测：
  `limits` / `errors` / `xlsx_scan` / `io` / `rules` / `transform` / `export` /
  `templates` / `batch`，`__init__.py` 只做对外接口和文档。
- **旧 API 全部保留**：`from cleaning import load_table, clean_data, ...` 一行都不用改，
  `tests/test_app_logic.py` 与 `tests/test_app_ui.py` **一行未改**，107 项照常全通过。
- **测试从 107 增加到 194**（v2.0.0 时口径；v2.0.1 起为 210）：新增 75 项逻辑 + 12 项端到端界面测试，
  覆盖表头行、上限覆盖、超时/分块、三种防护模式、编号模式、列变换与安全表达式、
  模板读写校验、批量 ZIP、以及 12 条真实页面流程。
- 依赖没有增加：仍然只有 streamlit / pandas / openpyxl（+ pytest 做测试）。

### 升级注意（从 v1.8.0 过来）

- 下载文件名变了（多了时间戳）：`清洗后_<原文件名>_<时间戳>.<扩展名>`。
- 页面多了第 4 步（进阶列操作）、第 6 步的导出选项、第 7 步（批量）、第 8 步（模板）；
  原来的「清洗前后对比」从第 4 步变成第 5 步。
- 默认行为不变：不勾任何选项时什么都不删、不改列；CSV 默认仍加英文单引号；
  XLSX 默认仍把编号当文本、`=` 开头文字仍按文本写。
- 直接 `import cleaning` 的旧脚本仍可用；只是包的内部路径变了（例如 `cleaning.io`）。

## 版本历史（v1.8.0 及更早）

**v1.8.0（体验与可靠性；不加新功能，只解决实际卡点）**

- **第一张表超限不再把整份文件打死**：默认读表时，超限的那张**跳过**、接着读下一张可用表，
  页面写明「哪些表被跳过、卡在行数还是列数」。以前是直接报错，选表框都渲染不出来，用户无路可走。
  点名选那张超限表时仍照实报错（不偷偷换表）；换表失败会退回默认表并保留选表框，页面不会只剩一句报错。
  所有表都超限时报错会列出**每张表**的名字和原因。
- **大文件状态提示**：读取/预检、换表、生成下载都有明确的「正在…」提示，手机上传大文件不再像卡死。
- **清洗明细与差异样例**：第 4 步新增「每一步删掉多少行」（删完全重复 / 按列去重 / 删空值行分开计），
  以及可选开关「查看被删掉的行样例（最多 5 行，含删除原因）」。样例默认关闭，勾了才多算那几行，
  大文件开销不变。
- **依赖拆开 + CI**：`requirements.txt` 只放运行依赖；`requirements-dev.txt` 放测试依赖并把
  streamlit 固定到 **1.66.0**（实测能跑 `AppTest` + `file_uploader` 的版本），
  `.github/workflows/tests.yml` 用 dev 依赖跑 `pytest -q -rs`，界面测试不会再被静默跳过。
- 去掉第 3 步里重复的「按所选列有 N 行重复」提示——第 4 步的每一步计数已经更准确，
  同一件事不再算两遍、说两遍。

**v1.7.1（只修 bug + 补测试，不加功能）**

- **修 XML 实体导致表名对不上**：工作表名里的 `& < > " '` 在 XLSX 里是实体（`Sales &amp; Marketing`），
  旧代码用正则取 `name` 属性，拿到的是没解码的原文，和 openpyxl 读出来的名字不一致——
  结果是「名称为 `Sales & Marketing` 的工作簿直接打不开」（报「找不到要读取的工作表」），
  按名选表、选表下拉框也跟着错。现在 `_xlsx_sheet_names()` 改用 stdlib `xml.etree.ElementTree`
  解析，实体自动解码；关系路径按 OOXML 规则解析（`/` 开头是包内绝对路径，否则相对 `xl/`，支持 `..`），
  并跳过 `TargetMode="External"` 的外部关系。
- **回归测试 +8**：逻辑 6 项（实体解码、按解码后名字选三张表、用未解码原文选表必须报错且列出真名、
  关系路径的绝对/相对/`..` 三种写法）+ 界面 1 项（下拉框显示真名、连续切换两张表）；
  另外测试总数从 91 → 99。

**v1.7.0（第一个带新功能的版本：能选工作表、能按列去重）**

- **多工作表可选读**：工作簿有多张表时，页面出现「选择要读取的工作表」，选哪张读哪张；
  以前只能读第一张有数据的表。选了不存在的表名会列出全部可选表名。
- **按指定列去重**：第 3 步新增「按指定列去重（保留第一次出现的行）」，例如按「订单号」去重，
  和原来的「删除完全重复的行」可以同时开。
- **预检策略随之改变**（重要，和 1.6 相反）：行列/单元格上限**只作用于将被解析的那张表**，
  默认读到第一张有数据的表就不再往下扫；其他工作表不解析、也不限额，只受 200MB 解压体积约束。
- **删掉「试表循环」**：解析阶段直接用预检选出的表名，不再一张张 parse 试过去；
  chartsheet（图表工作表）不计入工作表列表，也不会被当成数据表。
- 顺带加固：选表改为**按表名定位**而不是按序号；notes 里的工作表数量也只数真实工作表。
- 修验收发现的两处：① **带格式的空白封面页**（只刷了边框/填充、没有值）不再让整份文件被拒，
  解析后是空表就自动跳到下一张；② **`<dimension>` 不再参与列数判断**。

**v1.6.3（修正 1.6.2 漏掉的问题）**

- **修 XLSX 列数预检漏洞**：以前文件里有 `<dimension>` 就跳过真实单元格扫描，
  把伪造得很小的尺寸信息当列数，能绕过列数上限。现在 `<dimension>` 只当列数下界，
  列数一律按真实 `<c r="…">` 引用扫出来，超限立刻早停。

## 判定规则（重要）

- **重复行**：所有列的值都完全相同的行才算重复行，清洗时保留第一次出现的那一行。
  只有某一列相同、其他列不同的行 **不算** 重复。
- **按列去重**：只看你选中的那几列，值全部相同的行算重复，保留第一次出现的那行；
  其他列的值不参与判断。和「删除完全重复的行」可以同时开，顺序固定为
  **全行去重 → 按列去重 → 删空值行**，页面会说明每一步删了多少行。
- **缺失值**：空白单元格（没有内容，或只有空文本）算缺失值。
  - 数字 `0` 和文本 `"0"` 都是有效数据，不会被删。
  - 单元格里写的 `NA`、`null` 按普通文字保留，不当作空值。
  - 只含空格的单元格不算缺失，但会出现在「可疑格式」里。
  - 删除空值行只按你勾选的那几列判断，其他列的空值不影响。
- **表头行**：默认第 1 行；可以指定第 N 行。表头上面的行会被忽略并在页面说明。
  合并单元格造成的空白表头自动命名成「列N」；重复列名 pandas 会改成「金额.1」这种形式（加 `.序号`）。
- **可疑数据**：只提示「首尾有空格」和「疑似公式/注入开头」，**只提示、不自动修改**，需要人工确认。
  「疑似公式」与 CSV 导出防护共用同一个判断：剥掉前置空白/BOM/零宽字符后，以 `=`、`@` 开头，
  或以 `+`、`-` 开头的非纯数字（`-5`、`1e3`、`-1,000` 这类纯数字不算）。
- **列变换顺序**：**删列 → 类型转换（用原列名）→ 重命名 → 计算列（用新列名）→ 列顺序（用新列名）**。
  这样「要转换的列」下拉框里列出的就是原列名，不会因为刚改过名而对不上。
- **类型转换失败**：不删除、不改写失败值——保留原文，并在页面上提示「哪一列有几个格子没转成功、
  例如「约三百」」。
- **计算列不是代码执行**：只允许数字、列名、`+ - * / // % **`、括号和 `round()`/`abs()`；
  属性访问（`列.__class__`）、下标、lambda、推导式、`__import__` 全部拒绝。
  列名里有空格/括号时用方括号包起来，例如 `[单价（元）]*数量`；
  手机上打出的全角括号/运算符（`（ ＋ ＊`）会自动换成半角。

## 功能

1. 上传 `.csv` / `.xlsx`（默认上限 10 MB，可调），先查扩展名和大小，再解析；
   CSV 自动识别逗号/分号/制表符/竖线分隔。
2. 工作簿有多张工作表时可**选择读取哪张**；页面说明实际读的是哪张。
3. **可指定表头在第几行**（v2.0.0）；合并单元格造成的空表头自动命名。
4. 展示行数、列数、列名和前 10 行预览。
5. 检查：各列空值数量、完全重复行数、可疑格式。
6. 行清洗（默认都不做）：删除完全重复的行、按指定列去重、删除指定列中有空值的行。
7. **进阶列操作**（v2.0.0，可折叠）：列重命名、删列、调整列顺序、文本转数字/日期、计算列。
8. 清洗前后统计对比、每一步删掉多少行、可选查看被删掉的行样例（含删除原因）。
9. **规则模板**（v2.0.0）：保存/下载/上传 JSON 模板，一键还原整套勾选和列设置。
10. 点「生成下载文件」后下载清洗后的 CSV 或 XLSX：
    - CSV 三种公式防护模式（单引号 / 零宽空格 / 关闭）；
    - XLSX 编号字段「强制文本」或「尝试转数字」；
    - 文件名带原文件名和时间戳，不覆盖原文件；选项一变旧文件自动失效。
11. **批量处理**（v2.0.0）：多张工作表 / 多个文件分别清洗，打成一个 ZIP；
    单项失败只记原因，不影响其他项。
12. 读取/预检、换表、生成下载时都有「正在…」提示；超过 10 万行显示分块进度条。
13. 可配置硬超时（默认 60 秒，侧边栏/环境变量可调），超时给中文提示，不生成半成品。
14. 空文件、只有表头、损坏文件、伪装扩展名、超大文件、无法识别的编码都会给出中文提示；
    XLSX 的空封面页自动跳过并说明；超过行/列/单元格上限会拒绝并提示拆分。
15. 「虚构样例数据」演示：包含 1 行重复、3 个空值、1 个金额 0、2 处可疑格式，不含真实个人信息。
16. 手机友好：单列布局、收窄留白、下载按钮占满宽度。

### 读取规则

- **CSV 按文本读取**：保留 `00123` 这类编号，避免被自动改成 `123`。
  导出的 XLSX 默认也按文本写入；需要计算时在第 6 步选「尝试转数字」。
- **XLSX 保留单元格原有类型**；一次读一张工作表：默认挑第一个有数据的（空封面页自动跳过），
  也可以在页面上直接选。要一次读多张，用第 7 步的批量处理。
- **编码**：先按 UTF-8（含 BOM）读，失败再按 GB18030（兼容 GBK）读，并在页面提示。
- **解析失败不跳过**：CSV 格式错误会整体报错，不会悄悄丢掉坏行。
- **表头**：默认第一行是列名；指定第 N 行时，上面 N-1 行忽略并提示。没有表头的文件，
  第一条数据会变成列名（可以先用 Excel 补一行表头）。
- **CSV 分隔符**：自动识别逗号 `,`、分号 `;`、制表符、竖线 `|`，
  页面会说明这次按哪种分隔符解析；四种都没有的文件只解析出一列，页面会提示确认格式。
- **XLSX 公式**：读取的是 Excel 保存的计算结果（不是公式本身），导出时是数值；
  没有缓存结果的公式会显示为空。需要保留公式，请先备份原文件。
- **导出 XLSX 的公式安全**：`=` 开头的文字会强制按文本写入，不会被 Excel 当成公式。

### 批量处理（v2.0.0）

第 7 步打开开关后，两种来源可以一起用：

- **当前文件的多张工作表**：多选工作表，各生成一个文件（文件名是「原文件名_工作表名」）；
- **一次上传多个文件**：每个文件各生成一个结果；XLSX 只取第一张有数据的表
  （要多张表请用上面的工作表多选）。

所有项都用第 3、4 步当前的规则（包括表头行和列变换）。结果是一个 ZIP，
成功几项就打包几项；失败项在页面表格里写明原因，不会让整批失败。
ZIP 内同名文件自动加 ` (2)`，避免互相覆盖。

### 规则模板（v2.0.0）

第 8 步「清洗规则模板」：

1. 勾好规则后，填一个模板名称、点「保存当前规则为模板」；
2. 在模板列表里点「下载」，得到 JSON 文件（可以存到手机或发给同事）；
3. 下次上传同类表格，在第 8 步「上传之前保存的模板」，规则会自动还原；
   也可以点列表里的「套用」。

模板只存规则、不含数据；存在浏览器会话里，页面会话结束就没了（要长期保存请下载 JSON）。
当前文件里不存在的列会被忽略，页面会提示忽略了哪些。模板长这样：

```json
{
  "工具": "表格清洗小工具",
  "版本": 2,
  "名称": "订单表常用清洗",
  "保存时间": "2024-05-01 10:30:00",
  "规则": {
    "表头行": 2,
    "删除完全重复的行": true,
    "按列去重": ["订单号"],
    "删除空值行": ["金额"],
    "列重命名": [["金额", "总金额"]],
    "删除列": ["备注"],
    "列顺序": ["订单号", "总金额"],
    "转数字": ["总金额"],
    "转日期": ["日期"],
    "计算列": [["含税", "round(总金额*1.13, 2)"]]
  }
}
```

只写 `规则` 那一层（不带「工具/版本」外壳）也能用，方便手工改。
写错类型会在页面上给中文提示，例如「模板里的『表头行』应为大于 0 的整数」。

### 进阶列操作（v2.0.0）

- **列重命名**：文本框里每行一个 `旧列名=新列名`；全角「＝」也认。
- **删除列**：多选；**列顺序**：文本框里每行一个列名，点名的列排到最前面，其余按原顺序跟在后面。
- **类型转换**：分别多选「转成数字」「转成日期」的列。数字会去首尾空格、去合法千分位逗号
  （`1,000 → 1000`）；日期支持 `2024-05-01`、`2024/5/1`、`2024-05-01 13:00` 等。
  转不了的格子保留原文，页面上提示个数和例子。
- **计算列**：每行一个 `新列名=表达式`，可以引用前面刚算出来的列。
  例如 `总额=单价*数量`、`含税=round(总额*1.13, 2)`。
  除以 0 的格子留空并提示；列名写错会提示「不是当前的列名」并列出可用列。

## 公式注入防护

CSV 没有单元格类型，用 Excel/WPS 打开时，`=`、`+`、`-`、`@`、制表符等开头的文本可能被当成公式执行。
本版提供三种模式（第 6 步单选）：

| 模式 | 做法 | 适合 |
| --- | --- | --- |
| 加英文单引号（默认） | 危险开头的文本/列名前面加 `'` | 兼容性最好，各软件都能识别为文本 |
| 加零宽空格 | 前面加不可见的 `U+200B` | 单元格显示更干净；但搜索/文本比较会多一个字符 |
| 关闭防护 | 完全按原样导出 | 自己确认过数据、或给程序消费时 |

- `-5`、`+5`、`1e3` 这类纯数字在任何模式下都不加前缀，避免破坏负数等正常数据。
- 前缀会实际写进 CSV 文件；不同软件/版本对单引号的显示不一致（可能隐藏，也可能直接显示）。
- **XLSX 不需要这个开关**：`=` 开头的文字在导出时强制按文本写入，`+ - @` 本来就是文本；
  `tests/test_app_logic.py` 用 openpyxl 检查了单元格类型。
- 这不保证覆盖所有电子表格软件和宏场景，来源不明的文件请先核对内容再打开。

## 导出选项（v2.0.0）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| CSV 公式防护 | 加英文单引号 | 单引号 / 零宽空格 / 关闭三选一 |
| XLSX 编号字段 | 强制文本 | `00123` 保持文本；选「尝试转数字」后变 `123`，转不了的保留文本 |
| 文件名 | 自动 | `清洗后_<原文件名>_<YYYYMMDD-HHMMSS>.<扩展名>`，不会覆盖原文件或上一次导出 |

选项一改，之前点「生成下载文件」得到的旧文件自动失效，必须重新生成，避免拿到旧结果。
批量 ZIP 的名字是 `清洗结果_批量N项_<时间戳>.zip`，里面的文件是 `原文件名[_工作表名].csv|xlsx`。

## 资源限制

| 项目 | 默认上限 | 说明 |
| --- | --- | --- |
| 上传文件大小 | 10 MB | 解析前检查 |
| 行数 | 500,000 行 | 解析前预检 + 解析后确认 |
| 列数 | 1,000 列 | 解析前预检 + 解析后确认 |
| 单元格总数 | 2,000,000 个 | 行 × 列，解析前预检 + 解析后确认 |
| XLSX 解压后总大小 | 200 MB | 解析前检查，防压缩炸弹 |
| 单次处理硬超时 | 60 秒 | 侧边栏/环境变量可调，0 = 不限 |
| 分块阈值 / 块大小 | 10 万行 / 5 万行 | 超过阈值自动分块清洗并显示进度 |

**三种调整方式**（优先级从高到低）：

1. 界面左侧「高级设置 → 资源上限与处理超时」：只影响本次会话，不改全局；
2. 环境变量（部署时用）：

   ```bash
   export TABLE_CLEANER_MAX_UPLOAD_MB=20      # 上传上限（MB）
   export TABLE_CLEANER_MAX_ROWS=1000000      # 行数上限
   export TABLE_CLEANER_MAX_COLS=2000         # 列数上限
   export TABLE_CLEANER_MAX_CELLS=4000000     # 单元格上限
   export TABLE_CLEANER_MAX_XLSX_MB=400       # XLSX 解压后上限（MB）
   export TABLE_CLEANER_TIMEOUT_SECONDS=120   # 硬超时（秒，0 = 不限）
   export TABLE_CLEANER_CHUNK_ROWS=50000      # 分块大小
   export TABLE_CLEANER_CHUNK_THRESHOLD=100000  # 超过多少行开始分块
   ```

3. 代码：`cleaning/limits.py` 顶部的 `MAX_*` 默认值。

写错或写太小（例如 `TABLE_CLEANER_MAX_ROWS=很多行`）会静默用回默认值——部署时不该因为一个
拼错的变量就起不来。

**超时是协作式的**：在分块循环、大步骤前后检查。一次 pandas/openpyxl 的 C 调用没法从外部打断，
要做到真正抢占得把任务丢进子进程（多一份数据拷贝，手机内存更紧张）。所以超时表现为
「整批失败 + 中文提示」，不会产出半成品。

**检查时机**：CSV 在 `read_csv` 之前用 `csv.reader` 逐条读记录预检（引号内的换行算同一个单元格），
超过行数上限立即早停。XLSX 在 `openpyxl` 解析之前：

1. 先按压缩包条目汇总解压后大小（防压缩炸弹）；
2. 再用 `archive.open()` **流式**读工作表 XML，只读需要的字节，数真实 `<row>` 数量。

第 2 步不信文件自己写的 `<dimension>`——它被伪造成很小时，`read_only` 模式会**静默丢行**；
列数**只信真实单元格引用**（`<c r="…">`），`<dimension>` **完全不看**：写小绕不过上限，
写大也不会把 3 列的文件误判成 1.6 万列。行数只数真正的行标签 `<row r="…">`：
`<rowBreaks>`（分页符）不是数据行，按子串数会多算 1 行。预检通过后才真正解析，
解析后再用实际行列确认一次。

**多工作表策略**：限额**只作用于将被解析的那张表**。

- 页面上选了哪张表，就只扫、只限额哪张；没选时按工作簿顺序扫，遇到第一张有数据行的表就停下。
- **超限的表会被跳过**，不会让整份文件打不开；页面写明「哪些表被跳过、卡在哪」。
  点名选那张超限表时照实报错（不偷偷换表）；换表失败退回默认表，选表框还在。
- 只有**每张表都超限**时才整份报错，错误里列出每张表的名字和原因。
- 批量处理时，每一项各自限额、各自报错，互不影响。

## 命令行（CLI 预览版）

> **预览版声明**：参数兼容承诺自 v3.0 起算；v2.4.0 仍为预览版，允许调整参数，每次调整会记入 CHANGELOG。

```bash

```

| 子命令 | 用途 | 主要参数 |
| --- | --- | --- |
| `clean` | 按模板/开关清洗单个文件 | 输入文件、`--template`、`-o/--output`（必填）、`--report`、`--force` |
| `inspect` | 只检查不清洗，输出中文问题报告 | 输入文件、`--header-row`、`--report` |
| `template` | 查看/校验模板的字段、版本与规则摘要 | 模板文件、`--check`（只校验） |
| `batch` | 按同一模板批量清洗目录或多个文件 | 输入目录/文件、`--template`、`--out-dir`（必填）、`--export-format` |

- 不传模板时可以用开关：`--drop-duplicates`、`--dedupe-on`、`--drop-missing-in`、
  `--rename 旧=新`、`--drop-cols`、`--order`、`--to-number`、`--to-date`、`--computed 新列=表达式`。
- 输出文件默认**不覆盖**，已存在会报错并提示加 `--force`。
- 退出码：`0` 成功；`1` 输入/数据错误（文件不存在、格式不支持、模板损坏或版本过高、超上限）；
  `2` 参数用法错误（缺参数、输出路径不可写或已存在）；`3` 内部错误。
- 所有错误只输出中文提示，不打印英文 Python 堆栈；完整参数见 `table-cleaner <子命令> --help`。

## API 雏形（本地 HTTP，无鉴权）

```bash
table-cleaner-api --host 127.0.0.1 --port 8765
# 或者：python -m api.http_api --port 8765
```

只做三件事，数据只存在进程内存：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /api/jobs` | 提交一次清洗：`filename`、`content_base64`、可选 `template`（模板对象）或 `rules`（规则对象），可选 `export_format` / `formula_mode` / `number_mode` |
| `GET /api/jobs/{id}/result` | 取清洗后的结果文件（CSV 或 XLSX） |
| `GET /api/jobs/{id}/report` | 取本次运行的中文报告、步骤与说明（JSON） |

示例（Python 标准库提交，避免手写大段 Base64）：

```python
import base64, json, urllib.request

payload = {
    "filename": "orders.csv",
    "content_base64": base64.b64encode(open("orders.csv", "rb").read()).decode(),
    "template": {"template_version": 1, "规则": {"删除完全重复的行": True}},
}
request = urllib.request.Request(
    "http://127.0.0.1:8765/api/jobs",
    data=json.dumps(payload).encode(),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(request) as response:
    job = json.load(response)          # 201，含 job_id / rows_before / rows_after
with urllib.request.urlopen(f"http://127.0.0.1:8765/api/jobs/{job['job_id']}/result") as response:
    open("orders_clean.csv", "wb").write(response.read())
```

- **无账号、无登录、无权限、无任务队列、无结果持久化**；默认只监听 `127.0.0.1`，
  不要直接暴露到公网，只适合本机或可信内网。
- 任务最多保留 20 个（先进先出），服务重启即丢；请求体默认上限 32 MB。
- 错误统一返回中文 JSON：`{"错误": "..."}`；接口不承诺稳定性，后续可能调整。

## 部署

### 方案 A：局域网临时使用（推荐先这样）

按「手机浏览器访问」一节启动即可。适合自己或同事、客户在同一网络里临时用，无需域名和证书。

### 方案 B：Streamlit Community Cloud（免费公网）

1. 把本项目推到 GitHub **公开**仓库（不要放真实客户数据）。
2. 打开 https://share.streamlit.io ，用 GitHub 登录，新建 app。
3. 选仓库、分支，入口文件填 `app.py`，部署。
4. 免费实例无人访问会休眠，首次打开要等几十秒；上传大小和并发也有限制。

注意：本工具没有登录，公网地址任何人都能打开。只放演示数据，或只在交付演示时开放。

### 方案 C：自己的服务器（后续收费/定制）

一台 1 核 2G 起的 Linux 服务器（Ubuntu 示例）：

```bash
sudo apt update && sudo apt install -y python3-venv nginx
sudo mkdir -p /opt/table-cleaner && sudo chown $USER /opt/table-cleaner
# 把项目文件上传到 /opt/table-cleaner 后：
cd /opt/table-cleaner
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

用 systemd 守护（`/etc/systemd/system/table-cleaner.service`）：

```ini
[Unit]
Description=table-cleaner
After=network.target

[Service]
User=使用者用户名
WorkingDirectory=/opt/table-cleaner
ExecStart=/opt/table-cleaner/.venv/bin/streamlit run app.py --server.headless true --server.address 127.0.0.1 --server.port 8501
Restart=always
MemoryMax=1G
MemorySwapMax=0

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now table-cleaner
```

`MemoryMax` 是给单文件处理峰值兜底（30 万行导出 XLSX 实测约 680 MB）；
不需要 swap（`MemorySwapMax=0`），宁可让进程被 OOM 杀掉重启，也不要拖垮整机。

Nginx 反向代理（`/etc/nginx/sites-available/table-cleaner`）：

```nginx
server {
    listen 80;
    server_name 你的域名;

    # 上传上限要 ≥ 应用上限（默认 10 MB，见 TABLE_CLEANER_MAX_UPLOAD_MB）
    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8501;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;

        # 反向代理超时必须 ≥ 应用硬超时，否则用户先看到 504 而不是中文提示
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/table-cleaner /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

再按需用 certbot 配 HTTPS。

### 公网部署前必须设的两个数

1. **反向代理超时 > 应用硬超时**。示例：应用超时 60 s（默认）→ Nginx `proxy_read_timeout 120s`；
   把 `TABLE_CLEANER_TIMEOUT_SECONDS` 调到 120 → 代理就调到 180~300 s。
   反过来（代理比应用短）会让用户先看到 504 英文错误，而不是我们的中文提示。
2. **容器内存上限 ≥ 单次处理峰值**。示例：只处理 10 MB 内的 CSV → 1 GB 够用；
   要导出 30 万行 XLSX（实测峰值约 680 MB）→ 至少 1.5 GB。

Docker 示例：

```bash
docker run -d --name table-cleaner \
  --memory=1g --memory-swap=1g \
  --cpus=1 \
  -p 127.0.0.1:8501:8501 \
  -e TABLE_CLEANER_MAX_UPLOAD_MB=10 \
  -e TABLE_CLEANER_TIMEOUT_SECONDS=60 \
  -v /opt/table-cleaner:/app -w /app \
  python:3.12-slim \
  sh -c "pip install -r requirements.txt && streamlit run app.py --server.headless true --server.address 0.0.0.0"
```

Compose 片段：

```yaml
services:
  table-cleaner:
    image: python:3.12-slim
    working_dir: /app
    volumes: ["/opt/table-cleaner:/app"]
    command: sh -c "pip install -r requirements.txt && streamlit run app.py --server.headless true --server.address 0.0.0.0"
    environment:
      TABLE_CLEANER_MAX_UPLOAD_MB: "10"
      TABLE_CLEANER_TIMEOUT_SECONDS: "60"
    ports: ["127.0.0.1:8501:8501"]
    mem_limit: 1g
    cpus: 1
    restart: unless-stopped
```

`--cpus=1` 也是保护：多个大文件同时处理时，CPU 不会互相抢到看起来像卡死。

### 公网前加一层 Basic Auth（强烈建议）

本工具没有登录。最简单的做法是在 Nginx 上挡一层：

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd 你的用户名
```

在 `server { ... }` 的 `location /` 里加两行：

```nginx
auth_basic "Restricted";
auth_basic_user_file /etc/nginx/.htpasswd;
```

然后 `sudo nginx -t && sudo systemctl reload nginx`。
但应用本身仍然没有用户体系；不要把客户的真实数据长期放在无访问控制的环境里。

## 部署层还需要做什么

代码里的限制都是「单进程内」的保护，挡不住并发和恶意构造。生产部署时至少补上：

| 措施 | 怎么加 |
| --- | --- |
| 内存上限 | 容器 `--memory=1g`，或 systemd `MemoryMax=1G`（见上） |
| 请求超时 | Nginx `proxy_read_timeout 120s`（大于应用硬超时），应用侧 `TABLE_CLEANER_TIMEOUT_SECONDS` |
| 上传大小 | 应用默认 10 MB；Nginx `client_max_body_size` 要 ≥ 这个值 |
| 并发限制 | Nginx `limit_req_zone` / `limit_conn`，或 Streamlit 前置排队；容器 `--cpus=1` |
| 访问控制 | Basic Auth（见上）、Cloudflare Access、或只在内网开放 |
| 日志脱敏 | 不记录请求体；Nginx 默认 `$request` 不含上传内容，别加 `$request_body` |
| 版本核对 | 部署后跑 `python -m pytest --collect-only -q \| tail -1`，应为 306 |

Streamlit 本身的 WebSocket 连接也会占内存，并发数要按实例内存除以单次处理峰值来估。
模板只存在浏览器会话 + 用户下载的 JSON 里，服务器不落盘，不需要额外备份策略。

## 数据与隐私

- 本工具代码不会把上传内容写入磁盘或数据库，只在本次运行的内存里处理；
  页面会话结束后释放。
- **规则模板**只存规则（列名、勾选项），不含数据；存在浏览器会话里，用户自己下载 JSON 保存，
  服务器不落盘。
- 下载使用新文件名（带时间戳），原始文件不会被修改或覆盖。
- 运行环境的访问日志可能记录访问时间和 IP，但不会记录表格内容。
- 样例数据全部虚构。
- **不保证所有数据都正确**：本工具只做通用格式检查，不做业务规则校验，
  可疑格式也只是启发式提示。导出前请自己核对。

## 已知限制（买了要知道）

> 这些不是「以后会修」的承诺，是当前版本真实做不到的事。买之前请确认不影响你的场景。

| 限制 | 具体表现 | 为什么 | 怎么办 |
| --- | --- | --- | --- |
| XLSX 里已经是数字的长编号 | Excel 只会精确存 15 位有效数字；文件里编号要是数字格式，读进来时就已经丢了尾数 | 信息在 Excel 保存时就没了，工具无法恢复 | 在 Excel 里把该列设成文本再录入/粘贴；已有数据只能人工核对 |
| 「转数字」只保证 15 位以内 | 超过 15 位的编号保持文本（v2.0.1 起），不会被改成错数字 | 长度超过 float64 精度，转了就是错 | 长编号请保持文本；要计算的是金额/数量这类短数字 |
| 百分比、货币、自定义数字格式 | XLSX 导出后只保留数值：15% 显示为 0.15，¥1,000 显示为 1000 | 保留格式要整套单元格样式，属于新功能 | 导出后在 Excel 里重新设格式；或导出 CSV 自行处理 |
| 数据区合并单元格 | 只有左上角有值，其余读出来是空的（页面会提示数量） | 合并单元格没有「填充值」的语义，替用户填会改数据 | 删空值行前看提示；或在 Excel 里取消合并并填充 |
| 大 XLSX 每次操作都重读 | 20 万行 × 4 列的 XLSX 读一次约 8.4 秒，改一个选项就要再读一次 | 当前不缓存整张表（缓存会让内存翻倍） | 大表优先用 CSV；或一次把选项选好再操作 |
| 超时不是抢占式 | 极端大文件可能超过设定秒数才停下（在步骤之间检查） | 真正抢占要子进程+拷贝，手机内存更紧 | 用默认 60 秒 + 拆小文件；别一次塞 50 万行 |
| 带时区的日期 | 同一时区的日期会保留「当地时间的日期」，时区标记不保留 | Excel 单元格不支持时区 | 需要保留时区请用文本；混时区的整列会保留原文并提示 |
| 计算列算出的大整数 | 例如 `2**100`，页面预览和 CSV 都对，导出 XLSX 后会被 Excel 按 15 位有效数字显示（值被四舍五入） | XLSX 的数字单元格本身就是双精度 | 需要完整数字就导出 CSV，或把结果当文本 |
| 极老日期（如 1677 年） | 不同 pandas 版本解析结果可能不同（3.0 认成日期、2.2 保留文本） | pandas 版本差异 | 一般业务数据不会遇到；遇到就手工统一格式 |
| CLI 参数 | v2.4.0 仍是预览版，参数兼容承诺自 v3.0 起算 | 先证明库能脱离网页运行，避免过早冻结接口 | 脚本里调用前看 `table-cleaner <子命令> --help`；调整会记 CHANGELOG |
| HTTP API | **没有鉴权**，默认只监听 127.0.0.1，任务只存内存、最多 20 个 | 本版只验证库层可被程序调用，不做账号/权限/队列/持久化 | 只在本机或可信内网用；不要暴露公网，重启会丢任务 |
| 在线 Demo | 本版**未提供**在线 Demo | 没有可用的托管环境，且不在本版交付范围 | 用本地 `python -m streamlit run app.py` 或 CLI/API 试用 |
| Polars 引擎 | **内部预览**，不是默认引擎；CLI / HTTP API / Streamlit / 批量不暴露；未做 lazy/streaming、行级血缘、性能目标 | v2.4.0 先证明语义等价，性能与原生帧边界留给 v3.0 | 默认用 pandas；内部试跑需 `pip install .[polars]` 并显式传 `engine="polars"`，已知回落见 `docs/ENGINE_ALIGNMENT.md` |
| benchmark 基线 | 只有单机一次首版基线，未做跨机/多版本对比，未设 10% 回退门禁 | 本版只要求测出基线，不设提升目标 | 看 `benchmarks/BASELINE.md` 与 `benchmarks/ENGINE_BENCHMARK.md` 的环境与协议；换机重跑只比相对值 |
| 手机浏览器手工验收 | 本轮环境无法在手机里点一遍（读屏/截图不可用、端口不可达） | 环境限制，见上一节 | 交付前人工走一遍「真机验收清单」9 步 |

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示「只支持 .csv 和 .xlsx」 | 老 `.xls` 用 Excel 另存为 `.xlsx` |
| 提示「CSV 编码无法识别」 | 用 Excel 另存为「CSV UTF-8」再上传 |
| 提示「XLSX 无法打开」 | 文件可能损坏，或其实是改了扩展名的其他文件 |
| 提示「文件太大」 | 默认 10 MB；可在左侧「高级设置」临时调大，或用环境变量 |
| 提示行数/列数/单元格超限 | 按提示拆分文件或删掉不需要的列；也可调大对应上限 |
| 提示「找不到第 N 行可作表头」 | 把「表头在第几行」改小；确认文件真的有那么长 |
| 列名变成「列3」「列5」 | 合并单元格造成的空表头自动命名；第 4 步「列重命名」可以改 |
| 提示「处理已经超过 60 秒」 | 把文件拆小、少勾几张表/文件，或在左侧调大「处理超时」 |
| 页面出现「分块清洗」进度条 | 超过 10 万行自动分块，属正常；等它走完即可 |
| 计算列提示「不是当前的列名」 | 用页面上列出的列名；列名带空格/括号时写成 `[单价（元）]` |
| 计算列某格是空的 | 除以 0 或原文不是数字，页面有提示；先把那列转成数字 |
| 模板上传后某些设置没生效 | 模板里引用的列在当前文件不存在，页面会提示忽略了哪些列 |
| 导出的 CSV 开头多了一个 `'` | 默认的防公式前缀；可切到「零宽空格」或「关闭防护」 |
| 导出的 XLSX 里编号变成 123 | 选了「尝试转数字」；要保留前导零就选「强制文本」 |
| 导出的 XLSX 里公式变成文字 | 故意按文本写入，防止 Excel 执行公式 |
| 批量 ZIP 里少了一项 | 看页面表格「结果」列的失败原因；坏文件不会拖垮整批 |
| 手机打不开页面 | 检查同一 Wi-Fi、IP、电脑端服务、防火墙 |
| 页面一直转圈 | 看电脑终端有没有报错，更新依赖后重启服务；检查 Nginx 超时 |

- 改列变换 / 计算列白名单：`cleaning/transform.py`；白名单在 `_ALLOWED_BINOPS` / `_ALLOWED_FUNCS`，
  加函数前想清楚它能不能触碰文件系统或网络（不能）。
- 改批量：`cleaning/batch.py`（流程、错误隔离、ZIP 命名）；界面在 `app.py` 第 7 步。
- 改模板字段：`cleaning/templates.py`（校验、过滤、摘要）+ `app.py` 的「套用/保存」按钮。
- 改资源上限：`cleaning/limits.py` 顶部的 `MAX_*`（或直接用环境变量）。
- 改界面文案：`app.py`。判定规则的文字统一从 `cleaning` 引用，避免两处说法不一致。
- 加新的清洗选项：`CleanOptions` / `ColumnOps` 加字段（保持默认可不做事）→
  `cleaning/transform.py` 实现 → `app.py` 接控件 → 导出签名里带上新字段（否则用户拿到旧文件）→ 补测试。
