## 协议

- 数据集：小 1 万行 / 中 10 万行 / 大 50 万行；固定随机种子 `20231106`。
- 每档四列：18 位长编号（含少量完全重复行）、普通文本（含空值）、脏金额（普通数值 / 千分位 / 货币符号 / 空值）、混合日期（三种写法 + 非法日期）。
- 标准流水线：读取 → 全行去重 → 按订单号去重 → 删除客户名称为空的行 → 金额转数字 → 日期转日期 → 客户名称改名为客户 → 计算含税金额（金额*1.13）→ 列顺序（订单号、客户、含税金额）→ 导出 CSV（quote 公式防护）。
- 测量项：端到端、读取、清洗、导出耗时与进程内存峰值；每项跑 3 次取中位数。
- 内存峰值取子进程 `resource.getrusage(RUSAGE_SELF).ru_maxrss`；计时用 `time.perf_counter()`。
- 50 万行 CSV 必然超过 10 MB 网页上传上限，benchmark 只放宽「上传字节数」一项；行/列/单元格上限保持现行值（50 万行 × 4 列 = 200 万单元格，正好等于上限）。
- 历史列：v2.0.1 / v2.2.0 未建立 benchmark 套件，无法补测，对应列为「未执行」；本表是 v2.3.0 首个 pandas 基线的延续，v2.4.0 起按 `--engines` 追加引擎列，后续版本只追加、不覆盖历史列。

## 复跑方法

```bash
# 1. 生成/复用固定数据（小/中/大）
python -m benchmarks.generate
# 2. 每档跑 3 次，写回本文件（双引擎信息性对比）
python -m benchmarks.run --dataset all --repeat 3 --engines pandas polars
```

> 本次重复次数：3；结果表只保留中位数，逐次明细见上一节。
